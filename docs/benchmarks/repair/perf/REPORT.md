# 복구 후보 동일 조건 core 성능 측정

2026-10-06, Windows 10.0.26200, Intel Core i7-14650HX(논리 CPU 24), Node 24.15.0. 브라우저 경기와 빌드·다른 테스트를 정지하고 각 실행을 새 프로세스에서 순서대로 측정했다. seed 2026, 실제 production ModernWorld terrain Normal, FFA/Hard, 금·병력 무한/즉시 건설 없음, 300 tick 시작 보호, 1,200 tick(게임 120초)이다. 모든 현대 v2 실행은 인간 KOR 1명과 AI 293명, 최초 세력 294개를 사용한다. AI 수·사고 주기·실제 판단을 줄이지 않았다. mixed의 하/중/상은 100/91/102, low/high는 각각 293명이다.

비교 전 checkout은 보고 대상 commit `36d5ddebc37e1a731dadca9912ea39d0992297c8`의 읽기 전용 참조이다. 수정본은 그 commit 위의 작업 파일이며 브라우저 후보 식별자 `4bd7f36b1403`와 함께 검증한다. 이 식별자를 새 Git commit이라고 표시하지 않는다. 전체 `src/core/**/*.ts`의 파일명·원문 SHA-256 fingerprint는 다음과 같다. **9개 실행 모두 측정 전후 source가 같았다.**

## 표시 업데이트 producer의 CPU 비용

`RepairDisplayBenchmark.ts`는 실제 `ModernSystemsExecution.tick`에서 중첩 `ModernSystems.tick` 시간을 빼서 측정한다. simulation 코드에 벽시계 판단을 추가하지 않는다. producer는 기존 1Hz 전체 상태 clone과 수정본의 10Hz 변경 위치 튜플·변경 route patch를 포함한다. 초기화 tick이 포함되며 GPU·DOM·화면 렌더·Worker 전달·네트워크 latency는 포함하지 않는다. producer p95와 systems p95는 서로 다른 tick에서 나올 수 있으므로 전체 p95와 산술 합산하지 않는다.

## 재실행

작업 공간의 읽기 전용 `../OpenFrontIO-reported`를 해당 commit으로 준비하고 프로젝트의 설치된 의존성으로 실행한다. 다음은 한 실행 예시이며 결과 JSON 경로를 바꿔 각 조건을 **별도 프로세스**에서 순서대로 실행한다.

```sh
npx tsx tests/perf/RepairDisplayBenchmark.ts ../OpenFrontIO-reported docs/benchmarks/repair/perf/reported-mixed-1.json mixed 1200 2026
npx tsx tests/perf/RepairDisplayBenchmark.ts . docs/benchmarks/repair/perf/repaired-mixed-1.json mixed 1200 2026
```

나머지는 `mixed` 두 번째 실행, `low`, `high`, 수정본 `legacy`이다. `idle` 또는 AI를 끄는 조건은 이번 표에 사용하지 않았다. 원자료의 `wrapperHash`, `coreSourceHash`, 시나리오 hash와 최초 세력·편성 상태로 조건을 확인할 수 있다. 최종 브라우저/저장/교육 증거는 [통합 복구 검증](../../../ModernRepairVerification.md)을 참고한다.
