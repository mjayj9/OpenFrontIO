## Implementation limits

Color is supplemental identification: hundreds of colors cannot provide comfortable CVD separation by themselves. This patch does not claim a perceptual threshold for every adjacent pair or assign purchased territory patterns. It uses a shared registry, fixed-size generated candidates and cached nearest distances. Modern initial ownership additionally prioritizes already allocated tile neighbors; Classic retains the global fallback because borders do not yet exist when its players receive colors. Existing names, identity chips and the AI+ marker provide a free text distinction. Team variations remain within their team hue.

The local UI tests verify press/release/cancel behavior and actual command dispatch. Real browser verification and performance measurements are reported separately by the parent task. Upstream PR numbers do not imply a merged fix.

## Local regression verification

The six existing deployment-shell suites were rerun from a clean `git archive` of starting commit `e02eeba66b4801ebae0b686e1b0e4bc03fbf3654`, using unchanged test files and scripts on this Windows host. They reproduced **67 failures and 11 passes in 12.72 seconds**. The failures involve Windows `bash -c` quoting, absent `jq`, and `sh` not found; they do not establish a gameplay regression. The initial full-suite run overlapped implementation and therefore is not a pristine baseline. Client view regressions found during implementation were corrected and their affected suites rerun successfully.

The controls regression suites assert effective saved/default key ownership, exact modifier combinations, a single command per input, palette exhaustion without identical fill reuse, and mobile press/release/slide/cancel behavior. Browser and simulation performance measurements remain separate from these unit results.

A restored full player update originally allocated the new shared palette in a different order from the live game's staged tribe creation. The added `ColorIdentity` regression reproduced three identities changing colors. Ordering by existing controller kind and then stable id fixes that case while preserving GameView's simulation/replay iteration order. Team palettes now hold 400 candidates and do not recycle exact colors at 192 identities; tests cover 198 nation controllers in one team.

Saved modifier combinations were also tested through continuous camera input. Two regressions (Ctrl+Alt movement with unbound Alt actions, and explicit Ctrl+Shift movement) initially produced no pan. Tracking parsed physical codes and all physical modifiers, while freezing camera movement only during an active selection box, makes both work. Discrete command and continuous camera tests continue to ensure saved ArrowUp/Minus assignments cannot trigger the newly introduced default camera/zoom bindings.

Enhanced tribes in team matches use individual fills, with the shared gray Bot-team outline and an explicit Team label/swatch in the information panel. Basic tribes remain gray. Human and nation teams keep their existing team hue variations. This provides team and controller identification alongside color without modifying paid cosmetic choices.

Focused acceptance tests also load the generated modern-world terrain and run the core simulation: all 198 controllers and country ownership runs, all twelve requested selectable countries, Korea attacking North Korea, protection against spawn reroll, modern victory conditions, custom multiplayer Korea/Japan mapping, and snapshot continuation. The modern/core/input/save group passed 153 tests in six files (22.20 seconds). The save tests use a transactional in-memory IndexedDB double with real serialized and gzip-compressed core snapshots; real browser persistence is validated separately and must not be inferred from the double.

Its coverage includes gray basic versus colored enhanced Bot-team identities, shared gray team outlines, palette exhaustion, staged/live versus full/restore allocation, modern human flags, replay cosmetics, and unchanged command dispatch.

Modern initial color selection now prioritizes the weakest normal/protan/deutan/tritan separation from earlier allocated neighboring controllers, using global separation to break ties. Country ISO identities are mapped to stable world controller ids in a shared live/replay preallocation helper. Allocation examines at most 32 neighbor identities (the current world's maximum is 16), and does no runtime terrain scan. Colors stay fixed as conquest changes borders so restore/replay identity remains consistent. The seven targeted palette/view/replay suites passed 59 tests in 12.74 seconds. No minimum perceptual threshold is promised for every pair; labels and team/controller indicators remain necessary.

A late browser playtest reproduced the legacy structure color calculation warning on the expanded modern palette. An actual SettingsTheme diagnostic showed 16 unmet normalized difference targets on default and 7 on colorblind. The old function held LAB chroma while adjusting lightness, saturated its converted sRGB gamut and stopped at 51 iterations; it was bounded, despite the misleading “infinite loop” warning. colord.delta is normalized CIEDE2000, not the old comment's CIE76, and changing alpha to 1 left the measured difference unchanged.

The adjusted calculation makes at most 50 attempts, then uses neutral white/black while retaining original light/dark alpha. Modern 198-controller default/colorblind diagnostics now have zero warnings and all derived pairs meet the configured 0.5 difference target. Six focused suites passed 53 tests; whole tsc and focused ESLint passed. Territory and border palettes are unchanged. The current GPU StructurePass consumes its own palette/HSV/glyph styling rather than this cached PlayerView structure pair, so this fixes the derived-color calculation and warning; it does not establish rendered icon or WCAG accessibility.
